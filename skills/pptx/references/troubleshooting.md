# 故障处理

以下路径都相对于 `SKILL.md` 所在目录；执行前解析为绝对路径，不调用裸命令，不依赖当前工作目录。

- 环境、依赖或浏览器异常：运行 `scripts/pptx doctor`。
- 不确定从哪种页面起步：运行 `scripts/pptx starter list --json`，再只查看一个相关 starter。
- 页面结构失败：按照 `edit_slide` 返回的真实文件、行号、selector 和问题修复该页。
- 素材失败：依据检查结果修正当前页面的相对路径、文件格式或 `alt`；浏览器报告破图时重新导出可真实解码的文件，再在正式预览中人工核对实际比例和裁切，不扫描其他目录寻找替代文件。
- 浏览器检查失败：只修改问题所在页面，然后重新运行 `scripts/pptx status <项目> --json`。
- 预览陈旧：执行状态机返回的预览命令；不要直接修改 `预览.html`。
- 最终构建陈旧：执行状态机返回的构建命令，自动重新验证预览并生成 PPTX。

如果精确入口不存在或不可执行，报告完整路径并停止；不搜索替代入口，不直接调用内部 Python 模块绕过入口。

不直接编辑生成的 `预览.html`、`演示文稿.html` 或公共 runtime。程序在预览和构建前后必须保持所有 `slides/*.html` 字节不变。

- PPTX 文字导出遇到 CSS 伪元素文字或列表自动标记：将其写为普通 DOM 文字；列表可用 `list-style:none` 配合实际的 `•` 字符，保留阅读顺序。
- 源文字被旋转、裁切、复杂遮罩或效果处理且无法准确重建时：修正为支持的普通文字布局后再导出，不能静默改成不可编辑背景文字。
- 技能维护审计失败：读取维护输出目录中的报告，依据页码、对象、规则与实测边界修复技能或测试源稿，再运行 `audit-skill`；不要缩字或修改成品使其通过。
- 维护审计缺少实际渲染器：使用具备 PowerPoint 的环境运行 `audit-skill`；维护结果保留为未验证。普通 `build` 和 `export-pptx` 不依赖 PowerPoint。
